# VIP 会员与后端支撑设计

> 项目：趣工局（微信小程序 · 个人主体）
> 版本：v1.0（2026-09-23）
> 状态：**构思稿，待评审**。触发背景：小红书推广启动，「前 100 名送永久 VIP」活动需要用户身份体系支撑。
> 前置阅读：《首页升级方案设计》§5 皮肤工坊（SkinDefinition.unlock 已预留 paid 分支）、《体验优化与发展规划》商业化路线。

## 0. 一句话定位

**VIP 卖「表达与收藏」，不卖功能。工具永远全量免费，VIP = 皮肤通行证 + 收藏特权。**

理由：
1. 「三无良心」（无广告/无登录/无权限）是你全部宣传文案的立身之本（10 篇小红书里有 2 篇押注这个点），功能一旦上 VIP 墙，人设崩塌
2. 工具类目 + 虚拟支付的合规前提是「功能不被付费墙分割」
3. 皮肤是你唯一验证过的「愿意为好看付费」的资产（圣诞树皮肤投入了整个 M4）

## 1. VIP 权益设计（首版四项）

| # | 权益 | 说明 | 实现成本 |
|---|------|------|----------|
| 1 | **皮肤通行证** | 未来所有付费/限时皮肤免费使用。含「错过圣诞季免费领取」的兜底价值（非圣诞季想用圣诞树？VIP 直接用） | 低（unlock 判定加 vip 分支） |
| 2 | **VIP 专属皮肤** | 1~2 款仅 VIP 可用的皮肤。首发建议做「鎏金」深色金属风——与你的徽章风头像（icon02 深色金属质感）形成呼应，天然高级感 | 中（1 个 skin 文件） |
| 3 | **装饰物全解锁** | 工分照常玩，VIP 免工分解锁全部装饰（工分体系保留，照顾无 VIP 的收集乐趣） | 低 |
| 4 | **VIP 徽章** | 关于页 + 首页工局等级条旁的小徽章。低调、不进工具页、不搞用户等级墙 | 低 |

**「永久」的边界（必须写进兑换页文案）**：永久 VIP 指「当前及未来所有皮肤、装饰解锁权益永久有效」；所有工具功能对所有人永远免费，与 VIP 无关。写清边界避免未来过度承诺纠纷。

**不做的**：去广告（本来就没广告）、工具高级功能分层、签到返利、VIP 专属客服——都是人设雷区。

## 2. 「前 100 名永久 VIP」活动机制

### 2.1 为什么用兑换码而不是「先到先得按钮」

| 方案 | 归因 | 防机器人 | 名额控制 | 结论 |
|------|------|----------|----------|------|
| 兑换码 XHS100 | 每渠道独立码，数据可归因 | 码只出现在小红书笔记里 | 后端原子扣减，精确 100 | ✅ 采用 |
| 进小程序点领取 | 无法区分渠道 | 任意用户可领（包括不是从小红书来的） | 同样可精确控制 | ❌ 归因失效 |

后续渠道扩展：`XHS100`（小红书）、`DY100`（抖音）、`FRIEND`（朋友圈），同一套后端，码表配置即可。

### 2.2 用户流程

```
小红书笔记（码：XHS100）
   → 微信搜「趣工局」进小程序
   → 关于页 / 皮肤工坊顶部「兑换 VIP」入口
   → 输入 XHS100
   → 后端原子校验：码有效 && 名额未满 && 该 openid 未领过
   → ✓ 绑定 openid + VIP 亮起 + 庆祝动效（复用彩带引擎）
   → 兑换页实时显示「已领 37/100」
```

### 2.3 防线

- **超发**：云函数内事务执行「used+1」，两个用户并发领最后 2 个名额不会发成 3 个
- **重复领**：openid 唯一约束，一个微信号终身一次
- **码泄露**：码本来就要公开（小红书笔记里），泄露不构成风险；风险是「非目标用户领取」——100 个名额本来就先到先得，接受
- **频控**：兑换接口同 openid 10 次/小时上限（防脚本撞码）

## 3. 后端选型（关键决策：云开发 vs 自购云服务器）

你打算买云服务器，先看对比再拍板：

| 维度 | 微信云开发 | 自购云服务器 |
|------|-----------|-------------|
| **上线周期** | 2~3 天（环境+云函数即写即用） | **域名 + ICP 备案 1~3 周** + HTTPS 证书 + 服务端搭建，保守 3~4 周 |
| **openid 获取** | **云函数上下文直接拿 OPENID，免 wx.login + code2Session，用户零感知** | 前端 wx.login → 后端拿 code 换 openid，自己写 |
| **域名/备案** | 不需要（wx.cloud.callFunction 不走合法域名） | 必须：request 合法域名要求 HTTPS + ICP 备案 |
| **运维** | 无（腾讯托管） | 服务器安全、续费、监控、故障自己扛 |
| **费用** | 基础套餐约 19.9 元/月起，本活动调用量级下绰绰有余 | 服务器 50~100/年 + 域名 50/年 + 备案时间成本 |
| **与虚拟支付衔接** | **官方推荐路径**（虚拟支付服务端能力云开发原生支持） | 需自行对接开放平台 API |
| **扩展性** | 锁定微信生态，出不了小程序 | 自由：官网、下载、API、任何业务 |

**建议路径（推荐 A，不排斥 B）**：

```
A. MVP 用云开发：一周内 VIP 体系+兑换码跑通 → 10 月中随小红书帖上线，绝不影响 12/01 圣诞死线
B. 云服务器晚点买：等「虚拟支付申请被拒需要自建」或「要做官网/分发」时再上，届时云开发的用户数据可迁（就一张 users 表）
```

**为什么现在别急着买服务器**：你的圣诞硬死线是 11/20，备案流程（买服务器→买域名→提交备案→管局审核）均值 2 周以上且不可控，一旦备案卡住，整个 VIP 活动和圣诞皮肤互相拖累。云开发零备案，是这个阶段唯一不赌死线的选项。服务器是你迟早要买的东西，但不是这一周。

## 4. 数据模型（云开发）

```
集合 vip_users：
{ _openid,          // 云开发自动写入，主键
  vip: true,
  source: 'xhs100', // 归因渠道
  claimedAt: Date }

集合 vip_codes：
{ _id: 'xhs100',    // 码本身
  total: 100,
  used: 37,
  active: true,
  desc: '小红书首发·前100名' }
```

```
云函数 claimVIP（伪代码）：
入参 { code }
1. const { OPENID } = cloud.getWXContext()        ← 零成本拿身份，用户无感知
2. 事务：
   a. 查 vip_users[OPENID] 已有 vip → 返回「你已是 VIP」
   b. 查 vip_codes[code]：active && used < total → used+1
   c. upsert vip_users[OPENID] { vip: true, source: code }
3. 返回 { ok, remaining: total - used }
```

```
云函数 getVIP：入参空 → 返回 { vip: bool, source }（启动时静默查询，缓存 storage）
```

## 5. 小程序端改造点

| 改造 | 位置 | 说明 |
|------|------|------|
| 云开发初始化 | app.ts | `Taro.cloud.init({ env })`，weapp only，H5 跳过 |
| 兑换入口 | 关于页 + 皮肤工坊顶部 | 半透明小胶囊「🎁 VIP」，不抢视觉 |
| 兑换流程 | 新组件 | 输码 → 云函数 → 成功彩带动效（复用首页 confetti 引擎）+ 「已领 n/100」 |
| VIP 状态缓存 | storage `vip_status` | `{ vip, source, checkedAt }`，24h 静默刷新 |
| 皮肤解锁判定 | `skins/registry.ts` | `unlock` 增加 `{ type: 'vip' }` 分支；已有 `paid` 分支留给阶段二 |
| 装饰解锁判定 | `skins/decorations.ts` | `isVip()` → 全解锁 |
| VIP 徽章 | 关于页 + 工局等级条 | 小徽章 + 悬浮文案「永久 VIP · 来自小红书首发」 |

**「无登录」人设如何保持**：云开发全程不需要用户点任何授权按钮（openid 是静默的），用户视角依然是「没登录」。宣传文案里的「无登录」指的是「无注册表单、无手机号、无头像授权」——这个承诺不破。唯一变化：隐私政策文案需补一句「微信 openid 用于会员权益标记」。个人主体小程序本身不强制隐私协议弹窗，但补文案是负责任的做法。

## 6. 与虚拟支付的衔接（阶段二，不着急）

```
现在（免费期）          →  阶段二（虚拟支付开通后）
─────────────────────────────────────────────
前 100 名兑换码免费送      →  VIP 售价 ¥9.9~12.9 一次性买断
圣诞皮肤圣诞季免费领       →  新皮肤单卖 ¥3~6 或 VIP 全含
无支付                   →  道具直购（官方推荐形态，非代币）
```

- 兑换码体系与支付体系并存：活动送码永远有效，付费照常卖
- VIP 定价锚点：皮肤单卖 3~6 元，VIP = 3 个皮肤回本、后续白赚——「买断制通行证」心智
- 虚拟支付的开通条件（工具类目、认证、月限额 10 万、Android 1%/iOS 12% 费率）已在《体验优化与发展规划》商业化章节记录，届时云开发后端已就绪，接入成本低

## 8. 风险清单

| 风险 | 等级 | 对策 |
|------|------|------|
| 「永久 VIP」过度承诺 | 中 | 兑换页明示权益边界（§1），只承诺皮肤/装饰 |
| 云开发费用随用户量增长 | 低 | 兑换/查询调用量级极小（人均每天 <5 次）；免费额度告警设好 |
| 100 名额被羊毛党/脚本抢 | 中 | 码只在小红书笔记出现 + openid 频控；被抢走也是真实用户，可接受 |
| 云开发绑定微信生态 | 低 | 就一张 users 表，CSV 导出可迁任何后端 |
| 个人主体 + 无支付期间「送 VIP」被误解为变相收费 | 低 | 全程零支付、零金额展示，兑换页只有「领取」无「价格」 |
| 备案与服务器采购占用圣诞窗口 | 高（若走服务器路线） | MVP 云开发路线规避（§3） |
