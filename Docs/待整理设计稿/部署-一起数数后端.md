## 一键复现（首次部署或换服务器）

三个脚本按序执行，都在 `server/deploy/`（PowerShell 下用 `scp` + `ssh`，注意先把 CRLF 去掉）：

```powershell
$k = "$env:USERPROFILE\.ssh\mariana_deploy"; $h = "root@8.133.166.123"

# 0) 前置：DNS 已加 A 记录 counter -> 8.133.166.123（阿里云云解析控制台，1~10 分钟生效）
#    验证： nslookup counter.mariana66.xyz 223.5.5.5

# 1) 上传脚本并去 CRLF
scp -i $k server/index.mjs "${h}:/www/wwwroot/counter/index.mjs"
scp -i $k server/deploy/install-node.sh server/deploy/setup-service.sh server/deploy/setup-nginx.sh "${h}:/tmp/"
ssh -i $k $h "sed -i 's/\r$//' /tmp/install-node.sh /tmp/setup-service.sh /tmp/setup-nginx.sh"

# 2) 装 Node 24（国内镜像 + sha256 校验，避开宝塔 Node 管理器）
ssh -i $k $h "bash /tmp/install-node.sh"

# 3) 起 systemd 服务（需已存在 /www/wwwroot/counter/index.mjs）
ssh -i $k $h "node --check /www/wwwroot/counter/index.mjs && bash /tmp/setup-service.sh"

# 4) 签证书 + 写反代 vhost（两阶段：先 80 做 ACME，成功后写 443）
ssh -i $k $h "bash /tmp/setup-nginx.sh"

# 5) 端到端验收
scp -i $k server/deploy/smoke.mjs "${h}:/tmp/smoke.mjs"
ssh -i $k $h "sed -i 's/\r$//' /tmp/smoke.mjs; BASE_URL=https://counter.mariana66.xyz node /tmp/smoke.mjs"
```

期望输出：`passed 28, failed 0`。脚本会写入一条测试标签（结束时软删除）和一张测试照片，
跑完若想清干净：`systemctl stop counter && mv data/counter.db backup/ && mv data/photos backup/ && systemctl start counter`。

## 各步骤在做什么

**1. DNS** — 云解析加 `A` 记录：主机记录 `counter`，值 `8.133.166.123`，TTL 默认。已备案主域名加子域无需重新备案。

**2. `install-node.sh`** — 从 `cdn.npmmirror.com` 下 Node v24.12.0 二进制包，`sha256sum -c` 校验后解压到
`/usr/local/lib/nodejs/`，软链 `node/npm/npx` 进 `/usr/local/bin`。与宝塔 `/www/server/nodejs` 互不干扰。
末尾探测 `node:sqlite` 是否需要 `--experimental-sqlite`（v24 不需要）。

**3. `setup-service.sh`** — 写 `counter.service`：

```ini
ExecStart=/usr/local/bin/node /www/wwwroot/counter/index.mjs
Environment=PORT=8787
Environment=HOST=127.0.0.1      # 只有 nginx 能访问，公网打不到
Environment=DB_PATH=/www/wwwroot/counter/data/counter.db
Environment=TRUST_PROXY=1       # 让限流按真实客户端 IP 计数
Environment=NODE_NO_WARNINGS=1  # 屏蔽 SQLite experimental 警告刷屏
Restart=always / RestartSec=3 / NoNewPrivileges / PrivateTmp
```

**4. `setup-nginx.sh`** — 先只开 80 端口服务 `/.well-known/acme-challenge/`（webroot `/www/wwwroot/counter-acme`），
`certbot certonly --webroot` 复用服务器上已有的 LE 账户签发；成功后写入正式 vhost：80 端口 301 跳 https，
443 反代 `127.0.0.1:8787`，带 `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Proto`，
`client_max_body_size 4m`（照片接口 2MB 上限留一倍余量），`nginx -t` 通过才 `reload`。

**5. 小程序后台（只能你本人操作）** — 微信公众平台 → 开发管理 → 开发设置 → 服务器域名 →
**request 合法域名** 加：

```
https://counter.mariana66.xyz
```

只需这一项：所有接口（含照片）都走 `Taro.request`，照片是用 `ArrayBuffer` 作请求体直接 POST 的
（`counterApi.ts` 的 `rawUpload`，因此**不需要** uploadFile 合法域名）；照片读取是 `<Image src>`，
微信对 image 组件的网络图片不要求登记域名。
`counterApi.ts:25` 的 `COUNTER_API_BASE` 已是该地址，无需改代码。

## 环境变量速查

| 变量 | 线上值 | 说明 |
|---|---|---|
| `PORT` | 8787 | 监听端口 |
| `HOST` | 127.0.0.1 | 反代后置 127.0.0.1；默认 0.0.0.0 |
| `DB_PATH` | /www/wwwroot/counter/data/counter.db | 默认 `<代码目录>/data/counter.db` |
| `TRUST_PROXY` | 1 | 从 `X-Forwarded-For` 取真实 IP 做限流 |
| `ALLOWED_ORIGIN` | 空 | 只登记跨域白名单时才填；小程序请求不带 Origin |
| `TLS_KEY_FILE` / `TLS_CERT_FILE` | 未用 | TLS 由 Nginx 终结 |

## 备份（建议尽快加上，目前未自动化）

数据就是 `data/counter.db` + `data/photos/` 两坨，用户的纪念记录丢了不可恢复。
WAL 模式下**不要**热拷 `.db` 单文件，用 sqlite3 在线备份：

```bash
# /www/wwwroot/counter/backup.sh
sqlite3 /www/wwwroot/counter/data/counter.db ".backup '/www/wwwroot/counter/backup/counter-$(date +%F).db'"
tar -czf /www/wwwroot/counter/backup/photos-$(date +%F).tgz -C /www/wwwroot/counter/data photos
find /www/wwwroot/counter/backup -mtime +14 -delete
```

```bash
# crontab -e  （每天 04:30）
30 4 * * * bash /www/wwwroot/counter/backup.sh >> /www/wwwlogs/counter-backup.log 2>&1
```

> 服务器上若没装 `sqlite3`：`node -e "const{DatabaseSync}=require('node:sqlite')"` 也能备份，
> 或宝塔软件商店装 sqlite3。更省心的做法是把备份再传一份到对象存储/别台机器（异地）。

## 已知边界

- `node:sqlite` 仍是 experimental，Node 升大版本前先在测试机跑一遍 `smoke.mjs`。
- 照片按内容哈希去重存单目录，数量级到万张再考虑分桶。
- 限流是内存桶（进程重启即清零），够用；若日后要多实例需换共享存储。
- 单文件服务无鉴权外部依赖，`server/data/` 已在 `.gitignore` 内，不会误提交数据。
