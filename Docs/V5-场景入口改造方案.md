# 趣工局 V5 · 场景入口改造方案

> 状态：方案待确认
> 日期：2026-11-04
> 决策：首页改为「场景入口 + 工具库」两层结构，礼盒网格从"工具导航"变为"场景导航"

---

## 一、背景与判断

当前 21 个工具、39 个页面，首页同时承担「装饰性入口」和「工具目录」两种职责：

- 礼盒模式：21 个卡片铺满首页，工具越多越拥挤；
- 简洁模式：按分类列出全部工具，本质仍是目录；
- 两套入口都在做导航，维护成本翻倍，用户也缺少「什么时候用哪个」的主轴。

**问题不是工具数量，而是没有层级。** 新增一个工具不应该让首页多一张卡，而应该只是对应场景里多一行。

一句话定位：**趣工局是一个按场景收纳的趣味工具盒——先选场景，再选工具。**

---

## 二、信息架构

```
首页（场景入口）
├── 4 个场景礼盒（2×2）
│   ├── 解压一下      → 场景库页
│   ├── 学习陪读      → 场景库页
│   ├── 做点东西      → 场景库页
│   └── 生活小算      → 场景库页
├── 全部工具（次级入口，1 行文字链）→ 场景库页（全局模式）
├── 工局等级条（保留）
└── 皮肤 / 装饰（保留，只作用于 4 个场景盒）

场景库页 /pages/library/index?scene=fun
├── 返回 + 场景名 + 搜索框
├── 分类切换：本场景 / 全部工具
├── 工具列表（1 列，大点击区）
└── 最近使用（P1，可选）
```

任何工具最多 **2 次点击**可达：首页场景 → 场景库 → 工具。

## 三、场景划分（基于现有工具）

| 场景 | id | 工具数 | 包含工具 |
|------|----|--------|----------|
| 解压一下 | `fun` | 10 | 情绪粉碎机、电子木鱼、无限气泡纸、彩虹屁夸夸机、白噪音混音台、人生倒计时、借口生成器、转盘选择器、假装来电、趣味选择器 |
| 学习陪读 | `study` | 5 | 文言文陪读、汉字练字卡、字帖生成器、拼音注音器、简繁互转 |
| 做点东西 | `create` | 5 | 拼豆图纸生成、手持弹幕、文字转图片、图片小工具箱、文本批量替换 |
| 生活小算 | `calc` | 1 | 生活计算器（内含 11 个计算器） |

说明：
- 沿用现有 `category` 字段即可完成首版映射，不需要给 21 个工具逐个加新字段。
- 「解压一下」工具最多，场景库内可再分「解压」与「整活」两个小节：
  - 解压：粉碎机、木鱼、气泡纸、夸夸机、白噪音、倒计时
  - 整活：借口、转盘、来电、趣味选择器
- 「生活小算」首版只有 1 个入口，后续新增计算器时可继续收纳在同一张卡内。

## 四、首页改造

### 4.1 结构

- 顶部：等级条（紧凑型）+ 「全部工具」文字入口；设置、分享保留。
- 主区：2×2 场景礼盒，复用现有礼盒视觉与皮肤系统。
- 每个场景盒展示：场景 icon、场景名、一句说明、工具数量、3 个代表工具小图标。
- 底部：关于 / Design by Mariana 保留。

### 4.2 线框

```
┌──────────────────────────────────┐
│ 🏅 Lv.2  ▬▬▬▬▬▬  全部工具 21 →  │
│                                  │
│  ┌────────────┐  ┌────────────┐  │
│  │ 🎡 解压一下 │  │ 📖 学习陪读 │  │
│  │ 捏一捏，放空 │  │ 读、写、注音 │  │
│  │ 10 个工具    │  │ 5 个工具    │  │
│  │ 🥊🪵🫧       │  │ 📜✍️📝      │  │
│  └────────────┘  └────────────┘  │
│  ┌────────────┐  ┌────────────┐  │
│  │ 🎨 做点东西 │  │ 🧮 生活小算 │  │
│  │ 图、字、拼豆 │  │ 算清日常账  │  │
│  │ 5 个工具    │  │ 11 个计算器 │  │

│  └────────────┘  └────────────┘  │
│                                  │
│            关于 · Design by ...   │
└──────────────────────────────────┘
```

### 4.3 交互

- 点场景盒 → 进入场景库页，`scene` 参数带上场景 id。
- 场景盒保留现有"按下浮动 / 开盒"动效，但不再长按拖动排序。
- 皮肤（网格 / 星夜 / 圣诞树 / 玩具工局）继续作用在 4 个场景盒上；树景只需 4 个锚点，反而更稳定。
- 等级、工分、前缀、彩带规则不变。
- 移除「简洁模式」切换按钮与 `home_layout_mode` 分流；简洁列表的能力由场景库页承接。

## 五、场景库页

### 5.1 结构

- 顶部：返回、场景名、工具数。
- 搜索框：输入即过滤，可跨场景搜索全部工具；搜索时展示「全部工具」结果。
- 分类切换：`本场景` / `全部工具` 两个 chip。
- 工具列表：单列行式卡片，包含图标、名称、一句话描述、右箭头。
- 工具较多时按小节分组（例如解压 / 整活）。
- P1：最近使用（按本机打开记录，最多 4 个）。
- P1：收藏 / 隐藏（沿用现有 `home_hidden_tools` 存储）。

### 5.2 路由

- 新增页面：`pages/library/index`，放在主包，保证从首页秒开。
- 入参：`scene=fun|study|create|calc`；不传时默认展示全部工具。
- 工具详情仍使用现有各工具页面，不做改动。

## 七、分阶段实施

### P0：骨架跑通
1. 场景数据（描述、slogan、代表图标）。
2. `SceneHome` 2×2 礼盒，点击进入场景库。
3. 场景库页：本场景列表 + 全部工具切换。
4. 移除简洁模式入口与模式分流。
5. 埋点 `scene_open`，`tool_open` 带上场景。
6. 导引文案更新。

### P1：可用性
1. 搜索（名称 + 描述 + 关键词）。
2. 最近使用。
3. 收藏 / 隐藏（沿用现有隐藏列表）。
4. 场景库内的小节分组（解压 / 整活）。
5. 皮肤槽位与树景锚点微调。

### P2：清理与收敛
1. 删除 `SimpleHome`、`simple-home.scss`、`home_layout_mode` 相关代码。
2. 评估删除首页拖动排序引擎（`dragConfig` / `dragSort` / `homeOrder`）或仅保留开盒动效。
3. 清理用户自定义分类 / 改名能力的入口（或迁移到场景库的收藏机制）。
4. 更新关于页、开发日志、待办清单。

## 八、验收标准

- 首页首屏只有 4 个场景盒 + 等级条 + 全部工具入口，不再出现 21 张工具卡。
- 任一工具从首页最多 2 次点击可达。
- 搜索能在全部 21 个工具中找到目标。
- 4 套皮肤、树景、等级条、开盒动效正常。
- 新增第 22 个工具只需在 `tools.ts` 增加数据与 `category`，首页布局不变。
- `tsc --noEmit` 0 错误；`build:weapp` 通过；主包体积仍在限制内。

## 九、风险与对策

| 风险 | 对策 |
|------|------|
| 皮肤槽位从 21 改成 4，树景锚点失效 | 先改槽位生成逻辑，保留 4 个手工锚点；回归 4 套皮肤 |
| 老用户停在简洁模式 | 启动时忽略 `home_layout_mode`，直接进入场景首页；不迁移、不报错 |
| 用户自定义分类/排序丢失 | 首版保留隐藏列表；自定义分类与排序在 P2 明确下线并在关于页说明 |
| 场景盒信息量不足，用户不知道里面有什么 | 场景盒展示 3 个代表工具图标 + 工具数；场景库内首屏展示全部 |
| 主包体积增长 | 场景库页只做列表与搜索，不引入新依赖 |
| 埋点未配置导致无法评估 | 上线前在 MP 后台创建 `scene_open`，并给 `tool_open` 增加场景参数 |

---

## 十、明确不做

- 不新增工具，先完成结构收敛。
- 不引入后端、登录、云同步。
- 不改各工具内部页面，只改入口与导航。
- 不做用户自定义场景（固定 4 个场景，降低理解成本）。
- 不在本阶段重做视觉皮肤，沿用现有礼盒体系。
