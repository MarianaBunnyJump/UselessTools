> 项目：趣工局（微信小程序 · 个人主体）
> 文档版本：v1.0（设计稿，**待评审，未排期，不含任何代码改动**）
> 日期：2026-09-25
> 方法：按 frontend-design 流程产出——先定设计原则与 token，再核对我是否只是产出了「任何成长体系都会长成的默认样子」，确认差异化后才落笔。

## 0. 一句话定位

**成长系统是「你在趣工局的工龄」，不是「你要完成的任务」。**

设计原则（全部为既有决策的延伸，不新增玩法）：

1. **被动积累**：打开工具就长工分，没有任何「每日任务」「签到」「排行榜」——守住工具类目定位
2. **职级即身份**：等级给的是称呼、细节和外显资格，不锁任何功能
3. **与 VIP 划界**：等级给「身份与细节」（称呼、印章、边框），VIP 给「皮肤资产」（详见《VIP功能与后端设计》）；两者永不存在「不花钱就矮一头」的关系
4. **本机数据不作云端凭据**（沿用 workPoints.ts 既有声明）

## 1. 现状盘点

已有（v1，已编码）：工分公式、Lv.1~10 曲线（200/级）、十级称号（初来乍到 → 工局局长）、Lv.3 标题前缀、Lv.5 标题彩带、柱状图等级页、首页等级条。

v1 的四个缺口（本设计稿逐一回应）：

| 缺口 | 现状 | 本稿方案 |
|------|------|----------|
| 工分来源单一 | 只有「打开工具 ×10」 | 增加「核心动作」与「成就加成」两类来源（§3） |
| 没有成长叙事 | 等级页是数据陈列 | 以「工牌」为唯一核心视觉重做等级页（§5） |
| 特权多为「规划中」占位 | 10 个里 5 个未实现 | 全部落到可实现的特权，并给出优先级（§4） |
| 与 VIP 的关系未定义 | 两份文档各说各话 | 明确边界与联动点（§4.3） |

## 2. 设计方案（先于功能）

### 2.1 唯一的核心视觉：工牌

成长页的主角不是进度条，是一张**挂在挂绳上的工牌**：

```
        ┌─┐
        ││        ← 挂绳（主题色织带）
      ┌─┴─┴─┐
      │ 趣工局 · 工牌 │   ← 黄铜包边圆角卡
      │            │
      │   🏅        │   ← 职级徽章（黄铜印章样式）
      │  快乐工友    │   ← 职级称号（现有十级称号沿用）
      │   Lv.3      │
      │────────────│
      │ 工号 20260901 │   ← 首次打开日期即工号
      │ 工分  620    │
      └────────────┘
```

为什么是工牌而不是别的东西：整个产品的隐喻就是「一间小工局」——工分、工友、局长全是既有词汇；工牌把这些词汇收敛成一个实体。用户看到的第一眼是「我在这里上班的凭证」，而不是「我的会员等级」。

**全页只bold这一处**：工牌做出质感（黄铜包边 + 钢印压纹），其余一切保持安静的列表。

### 2.2 视觉 token（贴合既有体系，不引入新体系）

| Token | 值 | 用途 |
|-------|-----|------|
| 奶油纸 | `#FFF9F2` | 页面底（沿用全局） |
| 墨褐 | `#4A3B32` | 正文（沿用全局） |
| **黄铜** | `#C9A063` | 工牌包边、印章、进度条金属段（本系统专属色） |
| 工装蓝 | `#5B7A9D` | 图表、次级信息（工装布色，与马卡龙主色拉开） |
| 砖红 | `#E07856` | 钢印、晋升时刻的强调（暖红，非错误红） |

- 字体：沿用现有手写体栈（项目禁内嵌字体，字体不改，气质靠排版与印章质感撑）
- 质感关键词：**黄铜、钢印、工装布**——哑光金属与纸面压纹，拒绝金色渐变与发光（金色渐变留给 VIP 的「鎏金」皮肤，刻意区分）

### 2.3 唯一的动效时刻：晋升盖钢印

升级瞬间（进入成长页时检测到等级变化）播放一次：工牌上的新职级以**砖红钢印「哐」地盖下**（scale 1.4→1 + 轻微旋转 -6°→0 + 一次短震动），随后落款一行小字「已转正 · 2026.09.25」。不做礼花、不做金币雨、不循环——一次盖印就是全部仪式。其余场景零动效。

## 3. 工分来源（全部被动，无任务形态）

页面上以「**本月工分条**」呈现——一张工资条样式的收据，列的是你已经发生的事，不是你要做的事：

```
┌ 本月工分条 ────────────┐
│ 打开工具      每次 +10  │
│ 核心动作      每次 +4   │
│ 解锁成就      每次 +50  │
│ 每天第一次来   +20      │
│ （均为自动记录，无需打卡）│
└────────────────────┘
```

| 来源 | 数值 | 说明 |
|------|------|------|
| 打开工具 | +10 / 次 | 现状保留 |
| 核心动作 | +4 / 次 | 粉碎 1 条、捏爆 1 整张气泡纸、生成 1 条借口 / 夸夸、转盘转 1 次（按「次」不按「下」，功德敲击不计入，防无脑刷） |
| 解锁成就 | +50 / 个 | 一次性，与木鱼成就联动（15 个 = 最多 +750） |
| 每天第一次打开 | +20 / 天 | 「回来上班了」，无连续概念，断签无损失 |

数值关系：以轻度使用（每天打开 3 个工具 + 几个核心动作）估算，约 6~8 天升一级，全程 Lv.1→Lv.10 约 3 个月——够快到有反馈，够慢到不贬值。

## 4. 职级与特权

### 4.1 曲线与称号

- 保持 **Lv.1~10 与现有十个称号不变**（初来乍到 → 工局局长，已在等级页与用户认知中）
- 曲线从「固定 200/级」改为**前快后慢**：`120, 180, 240, 320, 420, 540, 680, 840, 1020`（累计可反推），前三级一周内可达，验证特权价值
- 迁移：工分由原始计数实时派生（不落盘），公式升级后存量用户工分只增不减，等级单调不回退，**无需迁移脚本**

### 4.2 特权表（填平现有「规划中」占位）

| 等级 | 特权 | 状态 |
|------|------|------|
| Lv.1 | 查看等级与成长进度 | 已实现 |
| Lv.2 | 称号「熟门熟路」 | 已实现 |
| Lv.3 | 首页标题前缀（快乐的/有趣的/好玩的） | 已实现 |
| Lv.4 | **新增 2 枚专属印花**：齿轮纹、工牌纹（进 patterns.ts，全用户可用的印花库扩充） | 新 |
| Lv.5 | 标题彩带 | 已实现 |
| Lv.6 | **标题前缀池扩容**（+「会玩的」「靠谱的」）+ 分享卡片黄铜细边框 | 新 |
| Lv.7 | 用户页高级工局徽章（黄铜印章样式头像角标） | 新 |
| Lv.8 | 装饰物工分九折（装饰物上线后自动生效） | 新 |
| Lv.9 | 「局长候选」：关于页彩蛋名单里出现你的工号 | 新 |
| Lv.10 | 终极局长徽章 + 分享卡片鎏金细边框 | 新 |

原则：特权全是**外观与称呼**，永不是功能与内容量——工具对所有人永远全量免费。

### 4.3 与 VIP 的边界（联动《VIP功能与后端设计》）

| | 成长等级（免费） | VIP（付费） |
|---|---|---|
| 给什么 | 称号、印章、细边框等**身份细节** | 皮肤通行证、专属皮肤、装饰全解锁等**资产** |
| 传递什么 | 「这里是你的工局」 | 「感谢你支持这间工局」 |
| 边界 | 不影响任何工具功能 | 不制造功能墙 |

联动点：VIP 徽章与等级徽章在用户页并列展示（两枚不同的印章，黄铜 vs 鎏金）；VIP 不加速等级，等级不替代任何 VIP 权益。

## 5. 成长页布局（改造现有 `pages/level/index`）

```
┌─────────────────────┐
│      NavBar 等级      │
│     （工牌 hero）      │   ← §2.1，全页唯一视觉重点
│                     │
│  ▓▓▓▓▓▓░░░  还差 180  │   ← 黄铜管进度条（细）
│                     │
│  本月工分条 ────────   │   ← 工资条样式收据（§3）
│  打开工具       +10/次 │
│  核心动作       +4/次  │
│  成就加成       +50/个 │
│  每天第一次来    +20    │
│                     │
│  职级阶梯 ──────────   │   ← 纵向阶梯（非宫格）
│   Lv.4 ─ 好玩行家 🔒   │
│  ▶Lv.3 ─ 快乐工友 ✦   │   ← 当前行：钢印高亮
│   Lv.2 ─ 熟门熟路 ✓   │
│   Lv.1 ─ 初来乍到 ✓   │
│  （每行右侧一行特权小字）│
└─────────────────────┘
```

交互规格：
- 工牌随陀螺仪/触摸有 ≤2° 的物理摆动（复用挂树卡片的摆动经验），除此之外页面无动效
- 职级阶梯行点击展开该级特权全文（渐进披露，不弹窗）
- 工分数字变化用一次性的滚动数字（进页一次），不轮询

## 6. 数据与存储

- 工分与等级：继续由 `usage_*`、各工具动作计数、成就表**实时派生**，不落盘（沿用现原则，公式升级即迁移）
- 核心动作计数：复用各工具现有计数（`crusher_total` / `bubble_total` / `praise_generated_total` / `excuse_generated_total` / 转盘使用计数），**零新增埋点存储**
- 新增键：`growth_seen_level`（记录上次查看时的等级，用于晋升钢印检测）；`growth_promote_date`（转正落款日期）
- 本机数据不作云端凭据（沿用现声明）
