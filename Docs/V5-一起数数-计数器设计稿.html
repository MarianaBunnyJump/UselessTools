动效规则

数字弹跳

每次 +1 / −1，数字以 0.18s 弹性曲线（cubic-bezier .34,1.56,.64,1）放大到 1.1 再回弹。只动数字，不动整板。

浮字「+1」

点击时从按钮旁飘出「+1 / −1」，1s 内上浮消散。连续点击时浮字叠加，形成敲击的节奏感（复用木鱼的浮字引擎）。

删除两步确认

小计数点的删除图标先变红（confirm 态），再点一次才真正删除。误删可撤销的代价大于两步确认的成本。

抽屉缓入

分享面板与添加弹层用 0.3s 上滑（cubic-bezier .34,1.3,.64,1），背景同步压暗。全部动效尊重系统「减弱动态」。

02数据模型（后端预留）

// 云服务器接入时的表结构草案（V1 先本地）
card {
  id, title, emoji, color,
  main: { value, unit, target? }, // 主计数
  points: [{ id, label, emoji, value }], // 小计数点
  owner, members: [openid...],
  version, updatedAt // 乐观锁
}

event { cardId, userId, target, delta, ts } // 增量事件
写入走增量事件（谁 +1 了哪个目标），服务器聚合出当前值——多人同时 +1 不丢数。
离线可数：本地先记，联网后按事件序补传；冲突按事件级 last-write-wins。
分享链接 = cardId 短链 + 4 位口令，新成员凭口令加入 members 后即可共同计数。

04边界与后续

本设计稿演示的是示例数据（喝水打卡 / 连胜 / 读书会），真实数据由用户创建。
协作、云同步、口令加入依赖你的云服务器部署 + 微信登录（待办 U-1~U-3），本稿只做接口预留。
可延展：目标达成庆祝（复用彩带引擎）、每日清零模式、皮肤工坊的记分牌皮肤。
