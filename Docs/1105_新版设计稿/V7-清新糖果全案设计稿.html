首页双版式 · 精选 / 全量

自定义规则

  • 入口：长按任意卡片直接进编辑态（无菜单弹窗）；或点顶栏「整理」。
  • 添加：点虚线「添加」卡 → 底部 sheet 列全量工具（已选置灰），点选即回填。
  • 上限 10：满 10 件时添加卡变为提示「货架满了，先移走一件」；下限 1：移除最后一件时 Toast「至少留一件常驻」。

底部标签栏 · 三页签，可整体收起

自定义 tabBar（custom-tab-bar），只在 首页 / 福利 / 我的 三个页签出现，进入任何工具页自动隐藏。担心挡内容可以整体收起。

规格

  • 三个页签：🏠 首页 / 🍬 福利 / 👤 我的。白底 + 顶部 1px 发丝线，无选中滑块，选中色薄荷深 + 字重 700。
  • 收起把手：顶边中央 34×14「⌄」把手，点按或上滑收起；收起后右下角浮出 38px「⌃」圆钮（唯一的轻影允许位），点按或下滑恢复。
  • 设置开关：我的 → 设置 →「底部标签栏」默认开；关掉 = 常驻收起，仅剩浮钮。
  • 手势：页面上滑浏览到第二屏时自动收起，回到顶部自动展开；跟手阈值 24px，无动画拖拽。
  • 不弹跳：收起/展开 140ms ease-out 位移，无回弹。
兼容注意：custom-tab-bar 在微信里是每 tab 页一份实例，切页签时同步选中态用 getTabBar()；收起状态存全局 tabbar_collapsed，与工具页互不影响。

福利页 · 每日领糖 + 糖果铺

签到拿的积分叫糖票（显示为 🍬 + 数字，单位「颗」）。糖票只做一件事：在糖果铺免费兑换工具与装扮——全程无任何付费入口。

糖票从哪来 被动为主，无任务清单

来源数额说明

工具页 · 三个模板管住 22 件

22 件工具按性格归进三个模板，各配一段规格；任何工具页不再自定义转场与阴影，只用全局令牌。工具页内没有底部标签栏、没有二级套娃——需要选择就弹 140ms sheet，需要历史就页内展开。

模板定义

模板性格与规格要点
A · 台面型一块主内容台面（大数字/主输出）+ 下方行列表。大数字用 DIN tabular + 一条 5px 糖色锚点条；历史改页内展开；新建改底部命令条。主色锚点取本工具糖色。
B · 表单型输入行（14px 圆角）+ 结果卡。结果卡内必配一句「局长的碎碎念」人话解读（糖色 wash 底），把数字变谈资。
C · 沉浸型全屏留白只留主角（木鱼/气泡纸/来电）。零框架 chrome，进度与计数小字放边角；敲击反馈即时（80ms），无任何浮层。

通用壳规格 所有模板共用

  • 页头：返回钮（38px 白底描边圆角方块）+ 工具名 15/700 + 右上唯一动作（历史/设置/更多）。
  • 进入速度：骨架 ≤200ms 只出现一次；语料、字库、图表等重资源 mount 后再拉；点进即能点。
  • 返回手势：系统侧滑 + 页头返回钮，无自定义转场。
  • 空状态：一句白话 + 行动按钮（如转盘历史空：「还没转过，转一把？」）。

用户数据上云 · 接在现有 server 上

复用「一起数数」后端（零依赖 Node + SQLite，server/index.mjs）的工程底子，新增 user.db 与一组 /api/u/* 接口。本机优先不变：所有工具离线可用，云端只做「签到防伪 + 糖票账本 + 配置备份」三件事。

架构与信任边界

微信小程序本机优先 · 离线可用
→
匿名设备令牌随机 32B · 只存 SHA-256
→
server/index.mjs+ /api/u/* 新路由
→
user.dbSQLite · WAL
上行：签到 / 使用事件 / 配置备份 —— 下行：糖票余额 / 已解锁件 / 配置恢复
谁说了算
本机：工具数据 · 精选货架 · 装扮展示
服务器：签到日期 · 糖票账本 · 解锁记录

表结构 user.db · 全参数化查询

表字段与说明
usersid · token_hash(唯一) · openid_hash(预留,可空) · created_at · nickname(可空) · avatar(可空)
checkinsuser_id(主) · last_date · streak · total_cycles —— 签到状态一行一人
points_ledgerid · user_id · delta · reason(checkin/streak/usage/unlock) · ref · created_at —— 只增不改的流水，余额由流水实时求和
unlockedsuser_id · item_id · unlocked_at —— 永久拥有，删号前不清
usage_dailyuser_id · day · tool_id · first_used —— 每工具每天一行，幂等记账
profilesuser_id(主) · home_config(JSON: 精选清单/排序/版式/设置开关) · updated_at —— 最后写入胜出

接口 全部 POST + X-Device-Token 头 · 白名单校验沿用现网关风格

接口入参 → 出参
/api/u/register— → {token}（本机生成随机令牌，服务端存哈希）
/api/u/me— → {balance, checkin:{today,streak}, unlocked[], profile?}
/api/u/checkin— → {delta, streak, balance}（服务端判日期与连击，重复签到返回幂等结果）
/api/u/usage{tool_id} → {delta?, balance}（当日该工具首行已存在则 +0，幂等）
/api/u/unlock{item_id} → {balance}（事务：余额够才落 unlockeds + 负数流水）
/api/u/profile{home_config, updated_at} → {ok}（updated_at 更新者胜）

同步与兜底策略

  • 签到：唯一必须联网的动作；离线时按钮灰态「联网后可领」。服务端日期为准，客户端时间不参与判定。
  • 糖票余额：本机缓存展示，以服务端 /api/u/me 为准；每次进「福利/糖果铺」静默对账一次，差值以流水重放解释。
  • 断网优雅降级：糖果铺可浏览可收藏，兑换时提示「联网后生效」；工具功能零影响。
  • 换机/清缓存：「我的 → 云同步」出示恢复码（= 注册时令牌的分组展示），新设备输入即接管账号；旧设备不踢出（个人工具场景，信任为先）。
  • 冲突：home_config 用 updated_at 最后写入胜；流水只增，永不覆盖合并。

防刷与安全

风险对策
重放签到服务端按 UTC+8 日期 + last_date 判定，重复请求幂等返回
伪造使用usage_daily 幂等 + 单 IP/令牌频控（沿用现有频控器）+ 每日 100 颗硬顶
多开刷糖令牌随机生成可多开——接受（无真金利益，防刷成本不值当）；openid 绑定字段已预留，未来需要再升级
注入/枚举全参数化 SQL · 输入长度与白名单校验 · 令牌只存 SHA-256（沿用一起数数既有声明）

合规与部署

  • 隐私指引：需在 MP 后台更新——新增收集「设备标识符（自生成匿名令牌）用于数据同步」；不取 openid/手机号/位置，头像昵称走微信原生授权不落服务器（默认）。
  • 部署：与一起数数同进程同机部署（新增路由），或独立 user.mjs 分进程；备份沿用「停服拷贝 / sqlite3 .backup」。
  • 成本：现 1C1G 即可承载；个人工具量级下 QPS 极低，无扩容需求。
  • 本机数据不作云端凭据原则延续：云端只同步糖票/解锁/配置备份，工具内容与使用历史不出本机。
