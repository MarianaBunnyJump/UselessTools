案例 1 · CARROT To-Do

来源链接

毒舌 to-do 工具，靠嘴贱文案和 ASCII 艺术胡萝卜机器人建立人格；UI 本身极度克制，是"可爱可以不油腻"的最硬证据。

截图来源：App Store 官方渠道（iTunes Lookup CDN），已本地验看 · 本地 assets/c-carrot-1~3.jpg

  • 色彩策略

    界面 95% 纯白，只用一种亮蓝（约 #00AEEF）做强调——顶部进度条、圆形主页按钮、解锁文案关键词；其余全是黑灰文字，没有第二种彩色。

  • 字体与排版

    粗黑无衬线大标题 + 常规字重列表项，行高宽松；列表项之间无卡片，靠垂直留白分隔。

  • 卡片与密度

    完全不用卡片，任务直接排在白底上，每行一个黑色对勾或圆形箭头；信息密度低但呼吸感强。

  • 层级与进入速度

    单屏即列表，点一下对勾直接出现，不进详情页；解锁内容（小猫、小游戏）是原地浮层而不是新页面，层级只有一层。

  • 动效克制

    完成任务只弹一下对勾 + 机器人台词刷新，没有页面转场；营销截图里刻意不展示花哨动效。

  • 可爱度处理

    可爱不靠颜色与渐变，靠嘴贱文案和 ASCII 线稿小猫；图形白底黑线，色彩投入近乎零。

  • 工具基因契合

    极高——证明人格化与趣味完全可以靠文案 + 极简图形实现；趣工局的 emoji 资产可以保留在白底上，不必给它配彩色渐变底。

案例 2 · 小睡眠

来源链接

国内 8000 万用户级的助眠、白噪音 app，按场景切换低饱和主题色；睡眠数据页用 pastel 阶段色条，大数字直接放白卡上。

截图来源：App Store 官方渠道，已本地验看 · 本地 assets/c-sleep-1~3.jpg

  • 色彩策略

    每个场景一个极低饱和主色（睡眠页淡蓝 #DCEEF7、白噪音页薄荷 #DFF0E4、AI 页淡紫 #E3E0F5），白色卡片浮在上面；数据阶段条饱和度全部压到 30-40%。

  • 字体与排版

    中文粗黑体大标题，大数字（96 分、9 小时 15 分钟）用中等字重无衬线；标签小字中灰，数字与说明之间大留白。

  • 卡片与密度

    数据用 24-28px 大圆角白色卡浮在 pastel 底上，卡片不重叠；图标页是 4 列圆形彩色按钮，圆内是白色线稿图标。

  • 层级与进入速度

    首页直接是场景 tab（睡眠、专注、冥想、呼吸），点一个大圆按钮即进入播放，无需选参数；历史数据平铺在首屏卡片里，不钻二级页。

  • 动效克制

    播放状态用底部漂浮胶囊条 + 小猫咪动画，不做整屏转场；场景切换是淡入。

  • 可爱度处理

    一只闭眼微笑的小白猫插画只出现在屏幕底部或角落，不占主内容区；彩色圆形图标是功能入口而不是装饰墙。

  • 工具基因契合

    高——证明糖果色可以是整屏 pastel 底而不是高饱和渐变，且大数字（96 分）放在白卡片上依然醒目。

案例 3 · 喵喵记账

来源链接

以收集猫咪为主题的萌宠记账 app，日式手账风：粗黑描边插画 + 圆形线稿分类图标；营销页高饱和，app 内反而克制。

截图来源：App Store 官方渠道，已本地验看 · 本地 assets/c-meow-1~3.jpg

  • 色彩策略

    营销页用一块暖芥末黄（约 #F5D547）铺底 + 同色系猫爪印暗纹；app 内界面反而是白底 + pastel 分类圆环（餐饮红、购物粉、日用蓝、交通蓝），色彩只出现在分类图标圆环上。

  • 字体与排版

    营销标题用超粗圆体 + 黑色描边（手账贴纸感）；app 内数字用常规黑体；分类图标下方是 11-12px 居中小字标签。

  • 卡片与密度

    记账键盘是大圆角白底（约 20px 圆角），数字键白底灰字；分类用 4 列圆形图标网格，圆与圆间距大，不拥挤。

  • 层级与进入速度

    打开即记账键盘（大数字输入框在顶部），选分类圆、输数字、点完成，全程不离开单屏；历史记录在同一屏下方列表。

  • 动效克制

    记账成功时猫会"变脸"（开心、委屈），是局部表情包切换，不是整屏动效。

  • 可爱度处理

    可爱全部由粗描边卡通猫插画承担（抱铅笔的猫、举喇叭的猫、穿兔子装的猫），UI 本身是干净白底 + 圆形线稿；不使用渐变、不使用毛玻璃。

  • 工具基因契合

    中高——营销黄底偏饱和，但 app 内界面反过来很克制；品牌色可集中用在某一个装饰元素（顶部一条色带或一只 mascot），其余界面回归白底。

对计数器页面的适配建议

  • 1

    记分牌大数字：去掉陶土 #E8795A 渐变底，保留米白底 #FFF9F2；数字用近黑深棕 #2D2A26、700 字重（从 900 降），下方加一条 4px 高的低饱和陶土、粉橙条作为"色彩锚点"——色彩从一整块渐变退到一条线。

  • 2

    小块列表：保留 5px 色条但饱和度从 80% 降到 45-50%（豆沙粉、雾霾蓝、鼠尾草绿、奶黄）；列表项之间用 12px 留白分隔而不是卡片背景；点击态用 4% 灰色压一下，不做高亮色块。

  • 3

    标记历史按钮：硬投影按压按钮改成白色圆形描边按钮（2px 陶土描边、无投影）；按下时整体下沉 1px + 背景 8% 灰，不用渐变。

  • 4

    历史抽屉：毛玻璃抽屉改成纯白底上滑抽屉，顶部 12px 浅灰拖拽条；时间戳文字用中灰 #999，不用半透模糊。

  • 5

    新建浮层：从浮层卡片改成底部 action sheet，白色 24px 大圆角；内部是圆形彩色图标网格（参考小睡眠白噪音页 4 列圆按钮），emoji 直接放在圆里。

  • 6

    动效时长：所有进入、退出动画压到 180-200ms（ease-out）；大块、小块切换不做缩放，做 120ms 透明度 + 8px 位移。

  • 7

    字体阶梯：大数字 104px、700 字重（从 900 降），字间距 +1；卡名 15px 常规、小块数字 24px、600 字重；圆体 Yuanti SC 作为品牌字保留（可爱来源），但把字重降一档避免笨重。

  • 8

    配色方案：主背景 #FFF9F2 保留，强调色从陶土渐变改为单色 #E8795A 平涂；辅助色板用豆沙粉 #F2C4B8、雾霾蓝 #B8C8D8、鼠尾草绿 #C8D8C0、奶黄 #F2E4B8。

实现成本（Taro / 小程序）低去掉渐变和阴影只是改 CSS（background / box-shadow），圆按钮和圆形图标 grid 是基础组件，无需新依赖；动效用 CSS transition 即可。
风险提示过度降低饱和会让计数器"失去活力"，需保留一个高饱和点（比如 + 按钮或当前选中项的小圆点）作为视觉焦点，否则会显得寡淡。
B

效率利落 · 工具质感 次选

像专业工具一样干脆：灰阶 + 单一强调色，分割线代替卡片，动效压到 150ms 以内，点击即反馈；emoji 只放在内容层，不进 UI 骨架。

灰阶+单一强调色分割线列表字重分层+负字距命令面板思维≤150ms 跟手

案例 1 · Linear

来源链接

面向产品与工程团队的 issue 跟踪工具，以"快"和设计质感著称。深色模式原生，用层级明度差代替阴影制造深度。

截图来源：Linear 官网与设计拆解博客，已本地验看 · 本地 assets/b-linear-1~2.jpg

  • 色彩策略

    深色原生——页面底 #08090a、面板 #0f1011，用背景明度阶梯代替阴影；几乎全灰阶，品牌靛蓝 #5e6ad2 只出现在 CTA 与选中态。

  • 字体与排版

    全系统 Inter Variable，标志性字重 510 做 UI 强调；大字号负字距压缩（72px 标题 -1.584px），三级字重 400/510/590，不用 700 粗体。

  • 卡片与密度

    单 issue 行高 36-40px，一行塞下 ID、状态点、标题、标签、指派人；看板卡 8px 圆角 + 1px 细边、无投影，"浮起"靠边框不靠阴影。

  • 层级与进入速度

    Cmd+K 命令面板是核心导航隐喻，选中 issue 是面板滑出而非新页面加载；hover 才浮现行内操作，默认状态干净。

  • 动效克制

    面板弹出约 120-150ms，hover 背景变化约 100ms；用背景不透明度代替位移，没有弹跳、没有缩放。

  • 可爱度处理

    不卖萌——无吉祥物、无装饰插画；趣味只藏在细节里（issue 描述里的 emoji、标签的彩色圆点）。

  • 工具基因契合

    高——骨架可直接借用：深色 + 灰阶 + 品牌点缀色能承载用户自己放进去的 emoji，UI 本身是"干净的容器"。

案例 2 · Raycast

来源链接

Mac 端命令面板启动器，整个产品就是一个"快速呼出的列表"。深色/浅色双主题，紧凑行高，右侧类型标签 + 底部快捷键提示栏。

截图来源：Raycast 官网与手动文档，已本地验看 · 本地 assets/b-raycast-1~2.jpg

  • 色彩策略

    深色画布 #07080a，边框 rgba(255,255,255,0.06)；品牌红 #ff6363 与信息蓝 #56c2ff 极少用，只在关键交互点出现；文字三级白/灰。

  • 字体与排版

    UI 全用 Inter 14-16px，500 做标签、400 做正文；一行内"左标题 + 中副标 + 右类型标签"三段式，密度极高；底部 Action Bar 用键帽样式提示下一步。

  • 卡片与密度

    没有卡片——整个面板是大列表容器，行间用 1px 半透明分割线或留白，选中行整行灰底高亮；分区标题是 12px 大写灰字，无背景块。

  • 层级与进入速度

    一个快捷键呼出，所有操作在一个列表里完成——输入即过滤，回车即执行；无二级页面、无浮层层级，底部常驻提示可执行操作。

  • 动效克制

    面板呼出约 100-120ms 淡入 + 轻微缩放（0.98→1.0）；列表选中行背景即时切换，键盘上下键滑动高亮跟手。

  • 可爱度处理

    本体不卖萌，但扩展生态全是彩色 emoji 小图标——一排彩色小图标本身带趣味，不需要额外装饰。

  • 工具基因契合

    极高——"单面板 + 密集列表 + 右侧标签 + 底部操作提示"可直接迁移做小块列表：左 emoji、中名称、右数字、底部一行操作提示。

案例 3 · Notion

来源链接

块结构笔记/协作工具，以"克制的分区 + 块级自由"著称。浅色优先、暖灰中性色，超薄分割线，极少用色块，靠排版和留白做层级。

截图来源：Notion 官网与设计更新博客，已本地验看 · 本地 assets/b-notion-1~2.jpg

  • 色彩策略

    暖白页面底 #ffffff，交替区块用暖灰 #f6f5f4（带黄调，像"好纸"）；文字 rgba(0,0,0,0.95) 近黑，唯一品牌蓝 #0075de 只用于 CTA 与链接——emoji 自带颜色是界面里唯一的彩色。

  • 字体与排版

    自定义 NotionInter，700 做标题、500 做导航、400 做正文；64px 大标题负字距 -2.125px；行高随字号收紧，字号越大越密。

  • 卡片与密度

    几乎不用实体卡片——块之间靠 1px 极淡分割线或留白区分；导航行约 36px，emoji + 名称 + 右箭头；卡片只在功能块出现且阴影 opacity ≤0.04。

  • 层级与进入速度

    左侧常驻导航树，点击即进入；块内联编辑，hover 才浮现操作按钮，"进入"不是打开新页面而是原地开始编辑。

  • 动效克制

    块展开/折叠约 150ms 高度过渡，无缩放无弹跳；选中行即时浅灰底——Notion 的快不是动效快，而是没有多余动效。

  • 可爱度处理

    效率工具里最"可爱"的——每页一个大 emoji 当图标，侧边栏一行 emoji + 名称；emoji 是页面的"头像"，不是 UI 装饰。

  • 工具基因契合

    极高——暖灰白底 + 极淡分割线 + emoji 做图标，比 Linear 深色更接近趣工局米底现状，改造路径最短。

对计数器页面的适配建议

  • 1

    小块列表改 Notion 式分割线列表：行高 48px，左 20px emoji、中 16px/500 名称、右 24px tabular 数字；行间 1px 淡分割线，去掉背景色块、色条与阴影；选中行整行 4% 浅灰高亮。

  • 2

    记分牌大数字去渐变改"压缩数字"：纯白/米白底，大数字 96px、heavy 字重、负字距 -1.5px，近黑 #1a1a1a；−/+ 改 ghost 圆按钮（1px 边框、透明底），「标记历史」做 12px 胶囊文字按钮。

  • 3

    历史抽屉改页内展开：记分牌下方就地展开历史时间线（高度 0→200px），不弹浮层、不遮罩；展开 120ms、收起 100ms，用户感觉"就在下面"。

  • 4

    新建浮层改底部"命令条"：点 + 后页面底部滑出 56px 贴底输入条，无遮罩——左输入框、中 emoji 选择、右完成按钮；滑出 100ms，是"底部多了一行"而非"弹了一个窗"。

  • 5

    动效全量压到 ≤150ms：行选中 80ms、面板展开 120ms、按钮按下 60ms；页面切换直接替换不滑动，去掉弹性回弹与 300ms+ 淡入淡出。

  • 6

    字体与配色：弃圆体换系统无衬线，层级靠字重 + 灰度（大数字 800 / 名称 500 / 数字 600 tabular / 时间戳 12px 灰）；陶土 #E8795A 降级为唯一强调色（选中数字/主按钮），其余灰阶。

实现成本（Taro / 小程序）中列表改造、字号字重调整、去毛玻璃和阴影是纯 CSS 改动；但历史抽屉改页内展开、新建改底部输入条涉及组件结构调整，约 1-2 天工作量，无需新依赖。
风险提示去掉卡片和浮层后"工具感"变强、趣味属性可能被削弱——需保证 emoji 图标系统足够醒目（20px、颜色够正），否则从"可爱工具箱"变成"普通效率工具"。

案例 1 · Apple HIG / iOS 设置

来源链接

iOS 内置「设置」是系统级极简的原型：浅灰 #F2F2F7 底上叠白色 inset 分组列表，行高 44-56pt，发丝分隔线，全程无卡片阴影、无渐变、无大圆角。

截图来源：Apple Developer HIG / UITableView 文档，已本地验看 · 本地 assets/a-apple-1~2.jpg

  • 色彩策略

    页面底 #F2F2F7、单元格纯白，整屏只有两个中性色；彩色仅出现在 29pt 方形 app 图标里，功能色（开关蓝/警示红）面积极小。

  • 字体与排版

    全用 SF Pro，主标签 17pt/regular、辅助值 17pt/60% 灰、大标题 34pt/heavy——靠字重和灰度而非字号堆砌层级。

  • 卡片与密度

    没有独立卡片，分组靠 20pt 上下留白 + 白色 inset 圆角容器区分；行密度高但不挤，每行只放「图标 + 主文 + 右值/箭头」。

  • 层级与进入速度

    二级页用标准 push（250ms 横向滑入），点击单元格立即高亮，没有中间弹层；设置项一屏到底，减少"点进去再加载"的等待感。

  • 动效克制

    开关切换 200ms 弹性、push 250ms，除此没有任何装饰性动效；选中态用单元格灰底一闪。

  • 可爱度处理

    不靠装饰，靠系统图标本身的彩色与圆角传递亲和力；文字与布局保持严肃。

  • 工具基因契合

    高——证明工具可以完全靠排版和留白成立，emoji 和品牌色可以独立出来当唯一的"可爱出口"。

对计数器页面的适配建议

  • 1

    记分牌大数字：去掉陶土渐变底和硬投影，改纯白/#F6F6F8 底上的近黑大号 tabular 数字（系统字体，约 96px）——数字本身就是焦点，不再需要底色块撑场。

  • 2

  • 3

  • 4

  • 5

  • 6

睡眠/专注/白噪音 app，App Store 多次推荐；以大幅留白 + 自然摄影著称，场景色底上控件退居二线。

  • 1

  • 2

  • 3

  • 4

    历史抽屉：毛玻璃改底部 sheet 白底，顶部 12px 浅灰拖拽条；时间戳中灰 #999，历史记录之间用 1px 发丝线分组（参考 Things 3 的 "This Evening" 分隔）。

  • 5

  • 6

实现成本（Taro / 小程序）低-中去渐变阴影是纯 CSS，发丝线 1px border，圆按钮和 emoji 选择器是基础组件；但需重新设计列表行高和字体阶梯，属组件层重构而非仅改样式。
风险提示纸感风在微信小程序里容易显"素"——用户已习惯 V6 厚重感，改版后可能反馈"太简单/没质感"，需保留一个高饱和点（+ 按钮）和一点温度（米底色），不能直接照搬 Things 3 的冷白。

对计数器页面的适配建议

  • 1

    记分牌大数字：走编辑部排印——大数字 tabular 等宽（约 96px/字重 500），上方加一行 11px 大写字距 1px 的 eyebrow 标签（当前工具名），去掉陶土渐变底色，"大数字 + 小标签"构成刊物式头条。

  • 2

    小块列表：卡片退位改报纸条目行——左侧粗体工具名（17px/600），右侧 tabular 数字（24px 严格右对齐成同一列），行之间 1px 发丝线；取消 5px 色条，用数字右对齐秩序做扫描线。

  • 3

    标记历史/−/+：改成 editorial 动作链——13px 大写等宽小标签（如 - 1 / + 1 / LOG），点击后数字就地刷新不弹层，减少"按钮 → 弹层 → 再确认"的层级。

  • 4

    历史抽屉：改"时间栏"双栏排印——左日期（13px 灰）右数值（tabular 右对齐），大留白和细字重，不要卡片和阴影；空状态用一句衬线文案占满。

  • 5

    新建浮层：极简成一行输入——一行标题输入 + 一个"保存"文字按钮，无多余表单。

  • 6

    字体阶梯与动效：建立四级字阶——display(大数字) / headline(工具名 600) / body / caption(11px 大写灰)；纸感米白 #FAF8F4 可保留但去陶土渐变，正文近黑 #1A1A1A，陶土只作链接/选中强调；切换和弹层 200ms 内以淡入为主。

实现成本（Taro / 小程序）中tabular-nums、发丝线、左右对齐网格是纯 CSS 易做；真正成本在"编辑部衬线感"——小程序默认无衬线系统字，衬线需引入 Noto Serif 类字体（包体/加载）并在小屏数字上做清晰度回归测试。
风险提示衬线在小字号和数字上易显模糊、会削弱"工具干脆感"；emoji 可爱度与衬线调性需磨合——建议先在记分牌大数字和历史栏试点，不要全页换衬线。

推荐优先级

三层推荐 + 两个特色选项，理由对应你的三条诉求：去油腻、进入更快、文字好看。

首选方向C · 清新糖果 · 可爱低饱和

三条诉求同时解决——低饱和/平涂/色条锚点直接去"油"，180-200ms 动效 + action sheet 替代毛玻璃浮层缓解"卡"，圆体降字重 + 数字 700 缓解文字疲劳；最贴"可爱但有质感"的品牌基因，emoji/圆体资产全保留，改动成本最低（纯 CSS）。

次选方向B · 效率利落 · 工具质感

"点击进入更快"解决得最彻底（动效 ≤150ms、历史改页内展开、新建改底部输入条）；Notion 暖白变体与现状最近，emoji 以内容层保留；字重分层 + 负字距是文字换血最系统的方案。

备选方向A · 纯白呼吸 · 系统级极简

字体与视觉换血最彻底、最素净（系统字体 + tabular 大数字 + inset 分组列表）；风险是易显素，品牌感靠 emoji 单点与陶土强调色拉回。

特色方向D · 纸感克制 · 温暖扁平

想保留暖纸温度、色彩即语义（Things 3 发丝分组 + dida 小圆点）的选它；风险与 A 相同，需保留一个高饱和点（如 + 按钮）。

特色方向E · 排版驱动 · 编辑部风

想要更强排印个性（衬线标题 / eyebrow 标签 / 报纸条目行）的选它；成本中（需引入衬线字体），建议先在记分牌大数字与历史栏试点。
